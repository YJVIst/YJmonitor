# 旧主控一次性升级到 0.11.6

旧发布私钥已丢失。v0.11.6 的主控、安装器、更新器和 Agent 改用 Ed25519 公钥 `5knizERV08A6pN/RMSh6ssDTK22NWm0U3+uCe8/4Azk=`。首次迁移由主控服务器管理员通过项目的 GitHub 正式仓库建立信任。请核对仓库名、以下脚本的 SHA-256 和发行说明。新安装直接使用普通安装器。

在旧 Rust 主控上进入 root shell，执行：

```sh
curl -fL --proto '=https' --proto-redir '=https' https://github.com/YJVIst/YJmonitor/releases/download/v0.11.6/migrate-signing-key.sh -o /root/YJ-migrate-0.11.6.sh &&
printf '%s  %s\n' 'a49e0cbb24c3ee48047fd289b981523cc6a4a1f08a2c8d1ae3c689d66c5eb77a' /root/YJ-migrate-0.11.6.sh | sha256sum -c - &&
bash /root/YJ-migrate-0.11.6.sh
```

脚本自动发现已登记更新器的 Rust 实例；多个实例使用 `--instance 实例名`。可先加 `--check` 校验签名和安装包。离线主控可用 `--release-dir /绝对路径` 指定包含正式 panel-stable.json 和安装 ZIP 的 root 所有目录。离线分发 Agent 还需按 Agent 发布源说明将本版 stable.json 和两个架构的 Agent 安装到该实例的缓存。

升级时主控短暂停服，保留原节点身份、管理员、私有状态、服务名和域名。程序保存旧版本与状态快照，健康检查失败会尝试恢复原服务。若更新器注册中断，重新运行同一命令可完成注册。未登记更新器的手动安装需要先按该实例的原部署说明注册更新器。

主控恢复后打开后台版本管理，选择在线且版本低于 0.2.4 的已登记节点，点击批量升级。主控最多同时处理两台，沿已认证的 Agent 连接建立 SSH，使用该节点既有的管理身份，在新签名和文件摘要验证通过后分发固定安装包。节点以原身份重连并上报目标版本后标记成功。离线节点待重连后再选取。缺少管理密钥或 SSH 账户没有 root / 免密 sudo 安装权限时，可在面板使用该节点的 SSH 安装凭据重新部署。脚本本身不触发节点变更。

迁移成功后，后续签名更新继续使用后台版本管理。
