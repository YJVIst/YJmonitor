# YJmonitor 仓库与管理命令

2026-10-20：账户更名后的当前地址为 YJVIst/YJmonitor。已有 Agent 接入失败请先按 [Agent 发布源修复](Agent发布源修复.md) 处理。以下保留 0.11.2 时的仓库迁移记录。

从 0.11.2 起，独立 Rust 仓库改名为 [coexacx/YJmonitor](https://github.com/coexacx/YJmonitor)。原仓库的提交、标签和历史发行保留。原 PHP 仓库 coexacx/yuji-probe 不变。

新安装按 [Linux 一键安装](Linux一键安装.md) 运行安装器。脚本自动创建低权限服务用户、私有数据目录与权限，安装后运行：

~~~sh
sudo YJ
~~~

YJ 区分大小写。旧 yuji-probe 命令作为一键安装实例的兼容别名保留；脚本遇到不属于本程序的同名命令会停止，不覆盖。程序包名称、服务名、状态目录和发布签名公钥保持兼容，无需重装已连接的 Agent。

## 已安装 Rust 版的一次性迁移

旧版下载器对仓库路径有严格校验，单靠 GitHub 的更名重定向不足以完成更新。以 root 运行：

~~~sh
curl -fL --proto '=https' --proto-redir '=https' --tlsv1.2 \
  https://raw.githubusercontent.com/coexacx/YJmonitor/v0.11.2/migrate-repository.sh \
  -o /root/YJ-migrate.sh
bash /root/YJ-migrate.sh
~~~

迁移脚本只读取已经注册的 Rust 实例配置，沿用本机受信任的更新器与原 Ed25519 公钥，切换固定发布仓库地址后验证签名、大小、SHA-256 和归档路径。下载或验证失败会停止；更新保留私有状态，重启主控并检查健康，失败使用原更新器恢复。不会运行新的网页安装向导或重置管理员。

迁移成功后重新注册签名更新器；一键安装实例自动增加 sudo YJ 命令。主控短暂重启会使管理员重新登录，Agent 自动重连。已有宝塔手动部署保留原目录、服务、HTTPS 和监听地址，通过原后台继续更新，不会被改成一键安装的路径。

若服务器注册了多个 Rust 实例，指定实例名：

~~~sh
bash /root/YJ-migrate.sh --instance rust-main
~~~

可在 /etc/yuji-probe-rust-updaters/ 中查看实例名称，填写文件名去掉 .json 的部分。不要输出或上传私有状态目录。

离线验收或内网部署可以增加 --release-dir，目录中必须有本版签名 panel-stable.json 和完整 ZIP，文件由 root 持有且不能由其他用户写入。验签和回退流程不会跳过。

## 宝塔手动部署

源码包内的 ops/prepare-service.py 自动准备服务用户和数据目录，命令见 [宝塔部署教程](Nginx-Rust部署教程.md)。手动实例的 systemd、Nginx 和更新器按教程配置；不要用一键安装菜单覆盖已有手动实例。
